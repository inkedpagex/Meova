🔴 TIER 1: HIGH SEVERITY (CRITICAL SECURITY & FINANCIAL ESCROW) — Items 1 to 35
================================================================================
1. [Security / Financial] Non-Atomic Direct Wallet Update on Circle Join: app/api/circles/[id]/join/route.js manually updates wallets table instead of atomic spendSparks() RPC, causing race condition double-spending under concurrent clicks.
2. [Security / Financial] Missing Escrow Rollback on Circle Join: If circle_members insert fails after sparks deduction in app/api/circles/[id]/join/route.js, sparks are lost forever without refund.
3. [Security / Financial] Payment Verification RPC Rollback Gap: In app/api/admin/verify-payment/route.js, if creditSparks fails after status is updated to 'approved', payment is marked approved without crediting Sparks.
4. [Security / Financial] Circle Creation Request Escrow Rollback: In app/api/circles/create/route.js, if pending approval insert fails after deducting 100 Sparks fee, user is not refunded.
5. [Security / Financial] UPI Decimal Slot Exhaustion (DoS): Attacker creating 99 intents across accounts locks all decimal slots (.01 - .99) in app/api/wallet/intent/route.js, blocking all user checkouts.
6. [Security / Auth] Admin Endpoint Database Verification: In app/api/admin routes, ensure role === 'admin' is strictly verified against public.profiles table rather than trusting cookie tokens alone.
7. [Security / Auth] Google OAuth Token Replay Attack: app/api/auth/google/route.js must verify token audience matches NEXT_PUBLIC_GOOGLE_CLIENT_ID and token has not expired.
8. [Security / Financial] Withdrawal Double-Debit Protection: app/api/wallet/withdraw/route.js requires row-level locking (SELECT ... FOR UPDATE) to prevent parallel double withdrawals.
9. [Security / Financial] Dispute Escrow Locking: When a meeting or gig is disputed, escrow must be locked in 'disputed' state rather than allowing host to complete and claim payout.
10. [Security / Data] User Post Deletion IDOR: DELETE /api/posts must enforce post.user_id === user.uid to ensure malicious actors cannot delete others' posts.
11. [Security / Data] Phone OTP Brute Force Threshold: Ensure phone_otps table purges record immediately after 5 failed attempts in app/api/users/verify-phone/confirm/route.js.
12. [Security / Data] Phone OTP Expiry Window: Ensure OTP expires strictly after 10 minutes and rejects any post-expiry verification attempts.
13. [Security / Financial] Negative Balance Prevention Constraint: Wallets table in Supabase must maintain CHECK (purchased >= 0 AND bonus >= 0 AND creator >= 0).
14. [Security / Financial] Strict Minimum Withdrawal Check: Server-side withdrawal API must reject amounts under 500 sparks ($5) regardless of client payload.
15. [Security / Financial] Maximum Single Withdrawal Cap: Server-side withdrawal API must enforce max 25,000 sparks limit per transaction to prevent wallet draining.
16. [Security / Data] XSS Injection via Profile Bio: Onboarding and profile edit APIs must strip HTML/script tags from bio and interests fields.
17. [Security / Data] Cloudinary Preset Hijack Protection: Ensure all frontend image upload components use 'Meova_unsigned' preset consistently and reject non-image MIME types.
18. [Security / DoS] Chat Message Payload Size Attack: POST /api/chats/[id]/messages must enforce 2,000 character limit to prevent memory exhaustion crashes.
19. [Security / DoS] Comment Flood Attack: POST /api/posts/[id]/comment must have a sliding-window rate limit (10 comments / min).
20. [Security / DoS] Feed Post Creation Spam: POST /api/posts must enforce 5 posts per 5 minutes per user rate limit.
21. [Security / DoS] Campus Presence Realtime Flood: POST /api/users/free-now must enforce 10 status toggles per minute cooldown.
22. [Security / Auth] Unauthenticated Root Access Gate: app/page.js must strictly check server session (getUserWithRole) and redirect unauthenticated guests to /login.
23. [Security / Financial] Self-Booking Prevention: POST /api/bookings must reject bookings where guest_id === host_id.
24. [Security / Financial] Self-Review Prevention: POST /api/reviews must reject reviews where reviewer_id === target_user_id.
25. [Security / Financial] Rating Bounds Clamp: POST /api/reviews must strictly clamp rating between 1 and 5 (Math.min(5, Math.max(1, rating))).
26. [Security / Financial] Zero Sparks Tip Exploit: Tipping endpoint must reject amounts <= 0, decimals, or non-integer numbers.
27. [Security / Financial] Meeting Date in the Past Exploit: Booking creation must reject meet_date timestamps occurring in the past.
28. [Security / Financial] Cron Auto-Refund Authorization: /api/cron/auto-refund must verify Authorization: Bearer CRON_SECRET header on every request.
29. [Security / Data] Block User Idempotency: POST /api/users/block must handle duplicate block gracefully without 500 error.
30. [Security / Data] FCM Token Hijacking on Logout: Logging out must invalidate the user's registered FCM token from active push sessions.
31. [Security / Financial] Gig Host Escrow Auto-Refund: DELETE /api/gigs/[id] must credit escrow back to host atomically via creditSparks RPC.
32. [Security / Financial] Meeting Code 6-Digit Brute-Force Lockout: PATCH /api/bookings must lock completion attempts after 5 consecutive failures for 15 minutes.
33. [Security / Financial] Freelancer Completion Code Lockout: POST /api/gigs/[id]/complete must lock attempts after 5 failures for 15 minutes.
34. [Security / Financial] Circular Pair Fraud Flagging: Completing 3+ gigs between the same 2 users must flag payout for manual admin review.
35. [Security / Data] Database Composite Index on Unread Notifications: Index (user_id, read, created_at DESC) to prevent table scan DoS under heavy load.
